# Module 3 — Semigroup and Monoid

Reference notes for [module 3 of the plan](../plan.md#module-3--semigroup-and-monoid). Examples are meant to be pasted into `cabal repl core` or evaluated with `-- >>>` comments; the newtypes live in `Data.Monoid` and `Data.Semigroup`, so import those first. Outputs and compiler messages were checked with GHC 9.10.3. The notes explain the ideas; the generator, the checker and the newtypes are yours to write.

## 1. `Semigroup`: one associative operation

```haskell
class Semigroup a where
  (<>)    :: a -> a -> a
  sconcat :: NonEmpty a -> a
  stimes  :: Integral b => b -> a -> a
  {-# MINIMAL (<>) #-}
```

The one law is **associativity**: `(x <> y) <> z == x <> (y <> z)`. The grouping does not matter, so it can be left out: `x <> y <> z`.

You have met three already:

| Type | `<>` | Example |
| --- | --- | --- |
| `[a]` | `++` | `"ab" <> "cd"` gives `"abcd"` |
| `Ordering` | first result that is not `EQ` (your `thenCompare`) | `compare 1 1 <> compare 2 3` gives `LT` |
| `Maybe a`, when `a` is a `Semigroup` | combines the contents, `Nothing` is skipped | `Just [1] <> Nothing` gives `Just [1]` |

`sconcat` combines a non-empty list (`NonEmpty`, from `Data.List.NonEmpty`): `sconcat ([1] :| [[2], [3]])` gives `[1,2,3]`. It needs `NonEmpty` because a semigroup has no value to return for an empty list. `stimes n x` combines `n` copies: `stimes 3 "ab"` gives `"ababab"`.

**Not every operation is associative.** `(1 - 2) - 3` is `-4` but `1 - (2 - 3)` is `2`, so subtraction is no semigroup. Neither is `Double` addition, strictly: `(0.1 + 0.2) + 0.3` gives `0.6000000000000001` and `0.1 + (0.2 + 0.3)` gives `0.6`. An average of averages is not the average either, which is the trap in the last exercise.

## 2. `Monoid`: a semigroup with an identity

```haskell
class Semigroup a => Monoid a where
  mempty  :: a
  mappend :: a -> a -> a
  mconcat :: [a] -> a
  {-# MINIMAL mempty | mconcat #-}
```

The laws add **identity** on both sides: `mempty <> x == x` and `x <> mempty == x`.

- `Semigroup` is a superclass (module 2, section 2), so a `Monoid` instance alone is an error:

  ```
  error: [GHC-39999]
      • No instance for ‘Semigroup Box’
          arising from the superclasses of an instance declaration
      • In the instance declaration for ‘Monoid Box’
  ```

- `mappend` is the same as `<>` and only exists for old code; never define it differently.
- `mconcat` combines a whole list and gives `mempty` for `[]`: `mconcat ["ab", "cd"]` gives `"abcd"`.

**Why the laws matter.** Associativity lets a long combination be split anywhere: in halves, in chunks across threads, as values arrive. Identity gives the answer for "nothing yet". Together they make `foldMap` safe to compute in any grouping, which is what section 5 builds on.

## 3. One type, several monoids

Numbers combine with `+` (identity `0`) and with `*` (identity `1`). Booleans with `&&` and with `||`. Both are lawful, so `Int` cannot pick one, and a type can have only one instance per class (module 2, section 10). The answer is a `newtype` per choice:

| Newtype | Wraps | `<>` | `mempty` | Example |
| --- | --- | --- | --- | --- |
| `Sum a` | `Num a` | `+` | `0` | `getSum (foldMap Sum [1 .. 10])` gives `55` |
| `Product a` | `Num a` | `*` | `1` | `getProduct (foldMap Product [1 .. 5])` gives `120` |
| `Min a` | `Ord a` | `min` | `maxBound` | `Min 3 <> Min 5` gives `Min {getMin = 3}` |
| `Max a` | `Ord a` | `max` | `minBound` | |
| `All` | `Bool` | `&&` | `True` | `getAll (foldMap (All . even) [2, 4, 5])` gives `False` |
| `Any` | `Bool` | `\|\|` | `False` | `getAny (foldMap (Any . even) [1, 3, 4])` gives `True` |
| `First a` | `Maybe a` | first `Just` | `Nothing` | `getFirst (First (Just 1) <> First Nothing <> First (Just 3))` gives `Just 1` |
| `Last a` | `Maybe a` | last `Just` | `Nothing` | the same gives `Just 3` |
| `Endo a` | `a -> a` | `.` | `id` | `appEndo (Endo (+ 1) <> Endo (* 2)) 5` gives `11` |
| `Dual a` | `Monoid a` | `<>` flipped | `mempty` | `getDual (Dual [1] <> Dual [2])` gives `[2,1]` |

Points worth noticing:

- **`Min` and `Max` are only monoids for `Bounded` types**, since the identity of `min` is the largest value: `mempty :: Min Int` gives `Min {getMin = 9223372036854775807}`. For `Integer`, which has no bounds, they are only semigroups.
- **There are two `First`s.** `Data.Monoid.First` wraps a `Maybe` and is a monoid. `Data.Semigroup.First` wraps the value itself (`First :: a -> First a`) and is only a semigroup, since there is no first element of nothing. The same goes for `Last`.
- **`Endo` composes right to left**, like `.`: `Endo (+ 1) <> Endo (* 2)` doubles first, then adds one.
- **`Dual` turns any monoid around.** `Dual (Endo f)` composes left to right.

## 4. Building monoids from monoids

The instances in `base` combine:

- **Tuples:** if `a` and `b` are monoids, so is `(a, b)`, combining each side separately. `mempty :: (Sum Int, String)` gives `(Sum {getSum = 0},"")`. This is how one fold computes several things at once.
- **`Maybe` adds an identity** to any semigroup: `Nothing` is `mempty`, and `Just` values combine with the inner `<>`. That turns `Max Integer`, a semigroup only, into a monoid where `Nothing` means "no elements seen".
- **Functions:** if `b` is a monoid, so is `a -> b`, combining the results.

```haskell
-- >>> foldMap (\x -> (Sum x, Just (Max x))) [3, 1, 4 :: Int]
-- (Sum {getSum = 8},Just (Max {getMax = 4}))
-- >>> foldMap (\x -> (Sum x, Just (Max x))) ([] :: [Int])
-- (Sum {getSum = 0},Nothing)
```

One traversal of the list, two results, and an empty list handled without a special case.

## 5. `foldMap`

```haskell
foldMap :: Monoid m => (a -> m) -> [a] -> m
```

`foldMap f` maps every element into a monoid and combines the results: `foldMap f = mconcat . map f`. The function picks the monoid, so the same list gives different answers with `Sum`, `Product`, `Max` or a tuple of them. Module 4 generalises it from lists to any `Foldable`.

## 6. Pseudo-random numbers without `random`

The `random` package is not in `base`, so module 3 builds its own generator. A pure generator is a function from a **seed** to a value and the **next seed**:

```haskell
next :: Seed -> (Word64, Seed)
```

Nothing is hidden: the same seed always gives the same sequence, which is what makes a failing test reproducible.

**Fixed-width arithmetic wraps.** `Word64` (from `Data.Word`) is an unsigned 64-bit integer whose arithmetic is modulo 2^64: `(maxBound :: Word64) + 1` gives `0`, and `(2 ^ 63 :: Word64) * 2` gives `0`. Both generators below rely on that instead of taking a `mod` by hand.

**Linear congruential generator (LCG).** The next state is `(a * x + c) mod m`. With `m = 2^32`, the constants `a = 1664525` and `c = 1013904223` are the classic ones from *Numerical Recipes*. It is three operations, and its weakness is in the low bits: the lowest bit of successive states just alternates, so use the high bits when you need a small range.

**SplitMix64.** The state advances by a fixed odd constant (`0x9e3779b97f4a7c15`), and each output runs the state through a mixing function of shifts, xors and multiplications. QuickCheck 2.19 uses it, through the `splitmix` package. Its paper (section "Further reading") gives the mixing function.

**Turning a `Word64` into a range** (say, an `Int` between `lo` and `hi`): `lo + fromIntegral (w `mod` (hi - lo + 1))` is the simple way. It is slightly biased when the range does not divide 2^64, which does not matter for tests.

## 7. Property-based testing

A unit test checks one input chosen by hand. A **property** states something for all inputs, `\x y z -> (x <> y) <> z == x <> (y <> z)`, and a checker tries it on many generated inputs, reporting the first one that fails. That is QuickCheck's idea, and the mini version needs three pieces.

**`Gen`: a generator is a function from a seed.**

```haskell
newtype Gen a = Gen (Seed -> (a, Seed))
```

Running a `Gen` takes a seed and gives a value plus the seed for whatever runs next. Combining generators means **threading the seed by hand**: to generate a pair, run the first generator, pass the seed it returns to the second, and return the seed the second returns. Forgetting to pass the new seed along makes both halves equal. Writing that plumbing a few times is the point here: modules 5 and 6 turn it into `Applicative` and `Monad` instances, and module 6 rewrites `Gen` on top of a `State` you build there.

Useful combinators to write: a number in a range, one element of a list, a list of generated values with a generated length, and a pair from two generators.

**`Arbitrary`: a default generator per type.**

```haskell
class Arbitrary a where
  arbitrary :: Gen a
```

Instances for `Int`, `Bool`, lists and pairs cover most properties. Your own types and newtypes get one each, which is how `Sum Int` values get generated for the law tests.

**`forAll`: run a property many times.** It takes a generator and a property, runs the property on a hundred or so generated values, and stops at the first failure, which it reports with `show` and, ideally, with the seed that produced it.

The open question is how `forAll` reports into the runner from module 1. `Testing.Runner` exports `TestResult` without its constructors, so another module cannot build one. Either the runner grows a way to make a failure or success with a message, or `forAll` builds its result through `assertEqual`. Decide which keeps the runner's interface smallest.

QuickCheck also **shrinks** a failing input to a smaller one that still fails. That is a stretch goal here.

## 8. Deriving through a newtype

A `newtype` has the same runtime representation as the type it wraps, so GHC can reuse an instance from one for the other. Two extensions do that, and a third makes the choice explicit:

| Extension | Lets you write | Meaning |
| --- | --- | --- |
| `DerivingStrategies` | `deriving stock`, `deriving newtype`, `deriving … via …` | says which mechanism derives each class |
| `GeneralizedNewtypeDeriving` | `deriving newtype (Num, Ord)` | reuse the wrapped type's instance |
| `DerivingVia` | `deriving (Semigroup, Monoid) via (Sum Int)` | reuse the instance of **another** type with the same representation |

```haskell
{-# LANGUAGE DerivingStrategies #-}
{-# LANGUAGE DerivingVia #-}
{-# LANGUAGE GeneralizedNewtypeDeriving #-}

newtype Age = Age Int
  deriving stock (Show)
  deriving newtype (Eq, Ord, Num)

newtype Score = Score Int
  deriving stock (Show)
  deriving (Semigroup, Monoid) via (Sum Int)

-- >>> Age 30 + 1
-- Age 31
-- >>> Score 3 <> Score 4 <> mempty
-- Score 7
```

`Int` has no `Semigroup` instance, so `deriving newtype` could not give `Score` one. `via (Sum Int)` borrows the `Sum Int` instance instead: same representation, the monoid you chose.

**What GHC generates.** `-ddump-deriv` (module 2, section 9) shows that both mechanisms produce `coerce`, a conversion between types with the same representation that costs nothing at runtime:

```
instance Semigroup Score where
  (<>)
    = coerce
        @(Sum Int -> Sum Int -> Sum Int) @(Score -> Score -> Score)
        ((<>) @(Sum Int))
```
