# Module 2 — Base typeclasses

Reference notes for [module 2 of the plan](../plan.md#module-2--base-typeclasses). Examples are meant to be pasted into `cabal repl core` or evaluated with `-- >>>` comments. Outputs and compiler messages were checked with GHC 9.10.3. The notes explain how the classes work; they deliberately stop short of the instances you write in the exercises.

## 1. Classes and instances

A class is a set of operations a type can support, together with what those operations must satisfy. An instance says how one type supports them.

```haskell
class Container f where
  empty  :: f a
  insert :: a -> f a -> f a

instance Container [] where
  empty  = []
  insert = (:)
```

- A **constraint** (`Eq a =>`) restricts a type variable to types with an instance. A function with a constraint works for every such type, and only for them.
- Under the hood, an instance is a **record of functions** (a *dictionary*), and a constrained function takes that record as a hidden argument. `elem :: Eq a => a -> [a] -> Bool` is, after type-checking, a function that receives the `Eq a` dictionary and calls its `(==)`.
- The type checker picks the dictionary from the **type** alone. That is why there can be only one instance per class and type (section 10).

## 2. Superclasses, default methods and minimal definitions

**Superclass.** `class Eq a => Ord a` means every `Ord` type is also an `Eq` type. An `Ord` instance without an `Eq` instance is an error:

```
error: [GHC-39999]
    • No instance for ‘Eq Shade’
        arising from the superclasses of an instance declaration
    • In the instance declaration for ‘Ord Shade’
```

The superclass also lets a function with `Ord a =>` use `(==)` without asking for `Eq a` separately.

**Default methods.** A class can define a method in terms of the others. `Eq` defines `x /= y = not (x == y)` and `x == y = not (x /= y)`, so an instance only has to write one of them.

**Minimal complete definition.** The `{-# MINIMAL #-}` pragma in the class says which methods are enough. You can see it with `:i Eq` in GHCi (`{-# MINIMAL (==) | (/=) #-}`). An instance that leaves out a required method gets a warning, not an error:

```
warning: [GHC-06201] [-Wmissing-methods]
    • No explicit implementation for
        either ‘==’ or ‘/=’
    • In the instance declaration for ‘Eq Color’
```

Take this warning seriously. With neither method written, `(==)` calls `(/=)` and `(/=)` calls `(==)`: the program compiles and then never returns. A missing method with no default body is no better: it compiles, and calling it throws `No instance nor default method for class operation *` (here, `*` left out of a `Num` instance).

## 3. `Eq`

```haskell
class Eq a where
  (==), (/=) :: a -> a -> Bool
```

The laws an instance is expected to satisfy, which the compiler does not check:

| Law | Statement |
| --- | --- |
| Reflexivity | `x == x` |
| Symmetry | `x == y` implies `y == x` |
| Transitivity | `x == y` and `y == z` imply `x == z` |
| Substitutivity | `x == y` implies `f x == f y` for every public `f` |
| Negation | `x /= y` is `not (x == y)` |

`Double` already breaks reflexivity: `let n = 0 / 0 :: Double in n == n` gives `False`.

Substitutivity is the one that matters for hand-written instances. If two values compare equal but some exported function tells them apart, code that replaces one by the other changes behaviour. With a fraction type, `1/2` and `2/4` should be equal, so either they are stored the same way or no function can see the difference.

## 4. `Ord`

```haskell
class Eq a => Ord a where
  compare              :: a -> a -> Ordering
  (<), (<=), (>), (>=) :: a -> a -> Bool
  max, min             :: a -> a -> a
  {-# MINIMAL compare | (<=) #-}
```

- `Ordering` is `data Ordering = LT | EQ | GT`.
- Laws: a **total order** (for any `x` and `y`, `x <= y` or `y <= x`), transitive and antisymmetric, and **consistent with `Eq`**: `compare x y == EQ` exactly when `x == y`.
- **Derived order:** constructors in the order they are declared, then the fields left to right, like a dictionary. `Nothing` comes before `Just`, so `compare (Just 1) Nothing` gives `GT`.
- `Data.Ord.comparing :: Ord a => (b -> a) -> b -> b -> Ordering` compares by a key: `comparing snd`. Combining two comparisons ("by this, then by that") is a monoid, the subject of module 3.

## 5. `Show`

```haskell
type ShowS = String -> String

class Show a where
  showsPrec :: Int -> a -> ShowS
  show      :: a -> String
  showList  :: [a] -> ShowS
  {-# MINIMAL showsPrec | show #-}
```

**What derived `Show` promises:** the output is valid Haskell that rebuilds the value, with only the parentheses needed.

| Expression | Output |
| --- | --- |
| `show (Just (-3))` | `"Just (-3)"` |
| `show [Just 1, Nothing]` | `"[Just 1,Nothing]"` |
| `show (P 1 (-2))` with a record `P { px, py :: Int }` | `"P {px = 1, py = -2}"` |
| `show (Just (1 :+: 2))` with `data Op = Int :+: Int` | `"Just (1 :+: 2)"` |

**Why `showsPrec` takes a number.** The `Int` is the precedence of the context the value is printed into, from 0 (nothing around it) to 11 (argument of a constructor application, which binds tighter than anything). A value whose own form binds more loosely than the context wraps itself in parentheses; `showParen :: Bool -> ShowS -> ShowS` does the wrapping.

```haskell
-- >>> showsPrec 11 (-5 :: Int) ""
-- "(-5)"
-- >>> showsPrec 11 (Just 'a') ""
-- "(Just 'a')"
```

A constructor application has precedence 10, so it needs parentheses when the context is above 10. An infix constructor uses its fixity: `infixl 6 :+:` behaves like `+`.

**Why `ShowS` and not `String`.** `a ++ (b ++ c)` copies `a` once, but `(a ++ b) ++ c` copies `a` twice, and a nested `show` builds exactly the bad shape. A `ShowS` is a function that prepends its text to whatever comes after, so pieces are joined with `.` and every piece is copied once: `showString "Just " . showsPrec 11 x`. The final `""` is passed only at the end.

`showList` exists so that `Char` can print a list as `"abc"` instead of `['a','b','c']`. Other types keep the default.

## 6. `Read`

```haskell
type ReadS a = String -> [(a, String)]

reads :: Read a => ReadS a
```

A `ReadS` parser returns every way to read a value from the start of the string, each with the rest of the input. An empty list means no parse.

```haskell
-- >>> reads "42 rest" :: [(Int, String)]
-- [(42," rest")]
-- >>> reads "x" :: [(Int, String)]
-- []
```

- `read` is **partial**: `read "x" :: Int` throws `Prelude.read: no parse`. In code that has to be total, use `Text.Read.readMaybe`, which is in `base`: `readMaybe "12x" :: Maybe Int` gives `Nothing`.
- The law is the round trip: `read (show x) == x`. Derived `Show` and `Read` are written to satisfy it, and a hand-written pair should too.
- Writing `Read` by hand is the hardest instance in this module, and modern code rarely does it. In the exercise it is a stretch goal: understanding `ReadS` is the point, since module 6 builds its parser on the same idea.

## 7. `Enum` and `Bounded`

```haskell
class Enum a where
  succ, pred     :: a -> a
  toEnum         :: Int -> a
  fromEnum       :: a -> Int
  enumFrom       :: a -> [a]            -- [x ..]
  enumFromThen   :: a -> a -> [a]       -- [x, y ..]
  enumFromTo     :: a -> a -> [a]       -- [x .. z]
  enumFromThenTo :: a -> a -> a -> [a]  -- [x, y .. z]
  {-# MINIMAL toEnum, fromEnum #-}

class Bounded a where
  minBound, maxBound :: a
```

- **Range syntax is sugar** for these methods, so any `Enum` type gets it: `[LT ..]` gives `[LT,EQ,GT]`.
- **`Enum` is full of partial functions.** `succ (maxBound :: Int)` throws `` Prelude.Enum.succ{Int}: tried to take `succ' of maxBound ``, and `toEnum 5 :: Bool` throws `Prelude.Enum.Bool.toEnum: bad argument`. A hand-written instance has to decide what happens at the edges.
- **The default range methods do not know the bounds.** They go through `fromEnum` and `toEnum` and keep counting, so with only those two methods written, `[B ..]` on a three-constructor type gives `[B,C,` and then whatever `toEnum 3` does. A `Bounded` type has to stop at `maxBound` itself.
- **Derived `Enum`** only works for types whose constructors have no fields. **Derived `Bounded`** works for those and for single-constructor types whose fields are all `Bounded`.
- **`Double` ranges are a trap:** `[0.1, 0.3 .. 1.0] :: [Double]` gives `[0.1,0.3,0.5,0.7,0.8999999999999999,1.0999999999999999]`. The rule lets the last element go up to half a step past the end, and rounding does the rest.
- `[minBound .. maxBound]` lists every value of a type with `(Bounded a, Enum a)`. It is the easiest way to test something on *every* value: `[minBound .. maxBound] :: [Bool]` gives `[False,True]`.

## 8. The numeric hierarchy

| Class | Superclasses | Main methods | Instances in `base` |
| --- | --- | --- | --- |
| `Num` | none | `+`, `-`, `*`, `negate`, `abs`, `signum`, `fromInteger` | `Int`, `Integer`, `Double`, `Ratio a`… |
| `Real` | `Num`, `Ord` | `toRational` | `Int`, `Integer`, `Double`, `Rational` |
| `Integral` | `Real`, `Enum` | `quot`, `rem`, `div`, `mod`, `quotRem`, `divMod`, `toInteger` | `Int`, `Integer`, `Word` |
| `Fractional` | `Num` | `/`, `recip`, `fromRational` | `Double`, `Float`, `Rational` |
| `Floating` | `Fractional` | `pi`, `exp`, `log`, `sqrt`, `sin`… | `Double`, `Float` |
| `RealFrac` | `Real`, `Fractional` | `truncate`, `round`, `ceiling`, `floor` | `Double`, `Rational` |
| `RealFloat` | `RealFrac`, `Floating` | `isNaN`, `isInfinite`, `floatDigits`… | `Double`, `Float` |

**Literals are overloaded.** `3` means `fromInteger 3` and `3.5` means `fromRational 3.5`: `:t 3` gives `3 :: Num a => a`, and `:t 3.5` gives `3.5 :: Fractional a => a`. A `Num` instance for your own type therefore gets integer literals for free, and a `Fractional` instance gets decimal ones.

**`Num` has no written laws**, but everyone assumes the ring laws: `+` and `*` associative, `+` commutative, `0` and `1` identities, `*` distributing over `+`, and `x + negate x == 0`. The one documented property is `abs x * signum x == x`. For some types (money, matrices) some methods have no sensible meaning, which is a good question to think about in the exercises.

**Conversions are explicit.** Nothing converts implicitly between numeric types.

| From | To | Function |
| --- | --- | --- |
| any `Integral` | any `Num` | `fromIntegral` |
| any `Real` | any `Fractional` | `realToFrac` |
| any `RealFrac` | any `Integral` | `truncate`, `round`, `floor`, `ceiling` |

`round` rounds halves to the **even** neighbour: `round 2.5` gives `2`, `round 3.5` gives `4`, `round (-2.5)` gives `-2`.

**`div`/`mod` versus `quot`/`rem`.** `div` rounds down and `quot` rounds towards zero, so they differ on negatives: `(div (-7) 2, mod (-7) 2, quot (-7) 2, rem (-7) 2)` gives `(-4,1,-3,-1)`. Each pair agrees with its own division: `div x y * y + mod x y == x`, and the same with `quot` and `rem`.

**`(^)` works for any `Num`.** `(^) :: (Num a, Integral b) => a -> b -> a` raises by repeated squaring: `x ^ 1000` takes 14 multiplications, not 999 (counted by tracing `(*)` on a wrapper type). Any type with a `Num` instance gets fast powers for free, which is the idea behind the Fibonacci exercise.

**Defaulting.** When a numeric type is left ambiguous, GHC picks the first type that fits from `default (Integer, Double)`, and `-Wall` warns about it. This is the warning the runner's smoke tests needed annotations for:

```
warning: [GHC-18042] [-Wtype-defaults]
    • Defaulting the type variable ‘a0’ to type ‘Integer’ in the following constraints
        (Show a0) arising from a use of ‘print’ at W.hs:4:8-12
        (Num a0) arising from the literal ‘2’ at W.hs:4:15
```

## 9. `deriving` versus manual instances

Haskell 2010 can derive `Eq`, `Ord`, `Enum`, `Bounded`, `Show`, `Read` and `Ix`. A derived instance is **structural**: it follows the shape of the type (constructor order, fields left to right) and knows nothing about what the type means.

That is what decides between the two:

- **Derive** when equality and order *are* the structure: enumerations, records of plain data.
- **Write it by hand** when the meaning differs from the structure. A fraction stored as `(1, 2)` and `(2, 4)` is the same number. A type with an invariant may need `Show` to go through its smart constructor. A case-insensitive name has to compare without case.

**See what GHC generates.** `-ddump-deriv` prints the derived code, which is the reference for the first exercise:

```bash
ghc -fno-code -ddump-deriv -dsuppress-all -dsuppress-uniques core/M02/Instances.hs
```

The output uses GHC internals in places: derived `Eq` for an enumeration compares constructor tags with `dataToTag#`, which needs `MagicHash` and `GHC.Exts`. `Ord` comes out as plain nested `case` expressions, and it is the one to compare against first.

## 10. Coherence and orphan instances

**Coherence:** there is at most one instance of a class for a type, in the whole program. Because the instance is chosen from the type alone, two instances in different modules would make the same expression mean different things depending on what was imported. A `Data.Map` built with one `Ord` order and searched with another would silently lose keys.

**Orphan instance:** an instance declared in a module that defines neither the class nor the type. GHC accepts it, and `-Wall` warns:

```
warning: [GHC-90177] [-Worphans]
    Orphan class instance: instance Show Pair
    Suggested fix:
      Move the instance declaration to the module of the class or of the type, or
      wrap the type with a newtype and declare the instance on the new type.
```

An orphan is a coherence risk, because nothing stops another library from writing the same orphan. The suggested fix is the general answer: a `newtype` is a new type, so it can carry a different instance legally. Module 3 is built on that idea (`Sum` and `Product` are two `Monoid` instances for numbers).

## Findings — exercise 1

Each derived instance in `M02.Instances` read against the hand-written one, from `ghc -fno-code -ddump-deriv -dsuppress-all -dsuppress-uniques core/M02/Instances.hs` (GHC 9.10.3, 2026-10-08). The tests in `test/core/M02/InstancesSpec.hs` already showed the two agree on every sample value; these are the differences in how they get there.

| class | derived | hand-written |
| --- | --- | --- |
| `Enum` | `enumFrom` and `enumFromThen` map the tag range up to `$maxtag`, or down to `0` when the second element is smaller | the same, with `[d .. Sat]` and `if d1 > d2` choosing the end |
| `Enum` | writes `succ`, `pred` and a range-checked `toEnum`, each with its own error message | `succ` and `pred` from the defaults, so they fail through `toEnum`'s message |
| `Ord` | writes `compare` and `(<)`; `(<=)`, `(>)` and `(>=)` come from `(<)` | `compare` only; the rest from the class defaults |
| `Eq`, several constructors | compares constructor tags first and answers `False` without looking at fields | a `case` on the pair with `_ -> False` last |
| `Eq`, `Ord`, enumeration | compares tags directly, with no `case` per constructor | `toInt`, a tag table written by hand |
| `Show` | `showsPrec` only; `show` and `showList` from the defaults | the same, except `DayOfWeek`, which writes `show` |

- **The `Enum` ranges were the right fix.** Overriding only the two open ranges, with the end picked by direction, is what GHC generates. `enumFromTo` and `enumFromThenTo` stay on the defaults in both, since they get the end from the caller.
- **`(<)` is an optimisation, not a correction.** The default `(<)` builds an `Ordering` from `compare` and checks it; the derived one calls `a2 < b2` on the last field instead of `compare a2 b2`. Writing `compare` alone is the minimal definition and is correct.
- **Tags are not out of reach, just not Haskell 2010.** `dataToTag#`, `tagToEnum#`, `==#` and `I#` need `MagicHash` and `GHC.Exts`. `toInt` is the portable version of the same idea.
- **Same pieces in `Show`.** `showParen (a >= 11)` is `d > 10`, `showSpace` is `showString " "` (`showSpace "x"` gives `" x"`), and constructors without fields ignore the precedence, which was the fix for `Just (Point)`.
- **What comes from the class.** The "Filling in method body" part of the dump lists the methods taken from defaults for every derived type: `/=`, `show`, `showList`, `max` and `min`.
